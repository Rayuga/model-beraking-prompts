# Functional workload reduction — r19

This report inventories the Functional rewrite before the root agent appends its separate session-credential criterion and shared-gate changes. The original **49 criterion IDs, binary types and weights remain** (weight sum **58**); the **9000-second judge timeout is unchanged**. No fresh scored Oracle/GPT result or measured execution-time improvement is claimed.

The old Functional material contained **11,805 words** (prompt 3,340, recovery 2,146, judge 6,319). The rewritten prompt, including recovery, and judge contain **8,565 words**, a **27.45% reduction**. The recovery addendum is merged and its separate file removed. Shared global-gate wording was preserved during these edits. Trusted paths now use /opt/common-ground-verifier.

Every negative-table row saves its complete observed exchange before assertions, catches failures independently, and verifies its fixture still permits the next case. A failed guard requiring a new clean fixture does not silently contaminate later cases. If browser Retry is absent or defective, exact observed server requests remain independently testable; there is no recovery-as-global-gate shortcut. Sharing evidence never shares pass/fail outcomes automatically.

The root agent additionally reduced implementation setup: the starter now supplies the SQLite schema and transactional seed, real session/password authentication, login/logout/session restoration and HTTP shell. Route inspection shows authentication/current-user/health routes, not ballot business routes. Agents still implement the business workspaces, role/eligibility/privacy projections, lifecycle and vote behavior, audit, idempotent receipts and durable browser recovery. This is concrete scope mitigation within the existing 7200-second agent budget, not a runtime guarantee or a near-complete business solution.
