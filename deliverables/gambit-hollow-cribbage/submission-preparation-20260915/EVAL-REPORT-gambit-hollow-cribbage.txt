Oracle

GPT-5.4-mini (high)
Functional: fifteen in the play is two
The 15 case awarded two, but the required 29-to-31 A play awarded five instead of exactly two.
Functional: moves out of order are refused
A fresh second discard by A was accepted before B discarded.
Functional: the show counts in order
Entries were ordered B/A/crib, but B scored 4 instead of the required 6 and final scores diverged.
Functional: a game is a sequence of hands
Next hand advanced identity and dealer state, but prior played cards remained and show totals were wrong.
Functional: pairs and last card in real play
Early pair checkpoints matched, but the final card omitted the required pair and last-card points.
Functional: show wins stop at each boundary
The three boundary games diverged before reaching the required show winner boundaries.
Functional: pegging scoring bench
The required five-card pile plus 2S returned five points instead of two.
Functional: complete club match
The first hand totals diverged and a later expected legal card could not be played, so the seven-hand match did not complete.
Functional: one player exhausted pegging
The exhausted-player journey produced incorrect run/go scoring and ended with B pegging 8 instead of 1.
Functional: last card thirty one
Initial 31 and run checkpoints worked, but final pegging/show totals diverged.
Functional: lost response retry ui
Intercepted discard was accepted server-side and Retry appeared, but reload lost the pending receipt so post-reload retry was unavailable.
Polish: keyboard controls and focus
Controls had accessible names and visible Tab/Shift+Tab focus; Enter switched seats and Space selected a card. After selecting 5♥ with Space, focus reset to BODY instead of a useful control.
Polish: responsive controls and reachability
Horizontal overflow was present at both sizes: scrollWidth 1359 at 1280px and 606 at 375px. The fixed-width ladder/history tables extend off-screen.
Visual: visual typography
Clear type scale distinguishes the title, section labels, seats, totals, controls, bench, and show breakdowns. Minor issues include small secondary labels and wrapped/clipped ladder/history identifiers.
Visual: visual color and contrast
The forest-green, mint, yellow, cream-card palette is cohesive, with distinct red/black suits and peg tracks. Open-game IDs and some secondary history text are visibly low-contrast on green panels.
Visual: visual spacing and layout
Board metrics, peg rail, seat cards, card grid, show panels, bench, and ladder use deliberate grouping. The long open-game list creates excessive vertical separation, while ladder/history tables overflow and clip content.
Visual: visual hierarchy and scanability
The active board has a clear metric row, seat grouping, turn panel, show breakdown, and commentary. However, the initial desktop view is dominated by many open-game rows, pushing the primary game state far below.
Visual: visual overall craft
A consistent board-game component language carries through SVG cards, peg board, panels, controls, empty states, scoring bench, and show history. Overflowing ladder content, raw history JSON, and low-contrast IDs prevent a top score.
Visual: visual responsive consistency
At 375px, the title, board metrics, cards, show breakdown, and bench stack coherently while retaining the desktop palette and styling. The ladder retains desktop table width, causing horizontal overflow and clipped columns/history summaries at the narrow viewport.
Gemini 3.7 Flash (high)
Functional: practice and scoring do not corrupt saved games
Invalid starting scores were incorrectly accepted by direct create requests, clamped, and created additional games instead of being refused.
Functional: pegging scoring bench
All listed experiments worked except duplicate [5C]/5C, which incorrectly returned 200 with pair points instead of refusing.
Functional: lost response retry ui
Forward-and-abort proved the server accepted the discard and the UI initially showed Retry Move, but after the required reload the retry control disappeared, so safe UI recovery could not be completed.
Polish: responsive controls and reachability
At 375×760 the document overflowed horizontally (scrollWidth 424 vs 375); saved-game tables extended to about 803px and ladder history was offscreen. Desktop 1280×800 fit.
Polish: illegal move feedback
At count 28, 9D was disabled as “unplayable,” but had no textual reason, title, description, or live announcement explaining that it would exceed 31. Valid AC still worked.
Polish: pending action and empty state
The no-game/practice view had a usable “Start Game at Table” control. However, while the first game POST remained pending, repeated mouse and keyboard activation produced another accepted 201 response and duplicate unfinished game IDs.
Visual: visual responsive consistency
The mobile table, navigation, cards, and scoring bench adapt coherently, but the ladder remains a wide two-column desktop layout with match history beginning offscreen, and the mobile show panel slightly exceeds the viewport. This creates visible horizontal overflow and loss of secondary-surface hierarchy at 375px.
