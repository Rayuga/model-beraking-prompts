# Presentation and gate review

The downloaded task mixed execution, persistence, aesthetics and usability into one binary `editor_craft` criterion. It also carried a same-origin constraint despite allowing network assets elsewhere. These were task-authoring problems, not evidence that the candidate model had failed a fair requirement.

The current presentation checks are four separate, equally weighted binary criteria:

1. At roughly 390 by 844, the editor, preview and console remain reachable. Tabs, drawers, stacked panes and intentional content scrolling are valid.
2. Important controls have meaningful labels or accessible names; three enabled controls show keyboard focus. Native controls and native focus indicators are valid.
3. One ordinary supported action receives useful visible feedback. This does not repeat execution correctness, source-line mapping or persistence checks.
4. Users can identify the editor, preview, console, current filename and saved library. Empty console/library states are valid. The separate functional criterion owns theme switching.

Visual keeps six topics: typography, colour/contrast, spacing/layout, hierarchy/scannability, overall consistency and responsive presentation. Each uses honest integer 1–5 anchors. A clear, coherent, conventional interface can earn 5; no custom branding, animation, novel design or perfection is required. A non-rendering surface gets raw 1, which installed RewardKit 0.1.7 normalizes to zero. This corrects the stale zero anchor in the unchanged template.

Render only checks that the public workspace opens with meaningful surfaces. Constraints only checks the stated health endpoint and continued workspace reachability. Neither gate demands authentication, saved writes, exact payloads or a particular route beyond the disclosed health URL. Health and durable browser behavior cannot prove the underlying SQLite or Express implementation; the rubric does not pretend otherwise.

Functional remains responsible for supported code execution, time limits, cancellation, source-line mapping, console behavior, revision conflicts, atomic refusals, durable records and restart. Its current 24 criteria have internal weight 49.5. Presentation changes do not award automatic passes or modify the 60%/20%/20% dimension shares.

All 53 workbook judgment rows and all 48 deterministic inventory names are represented in `QC_REVIEW.xlsx`. The private official checker executables and paid Oracle/model runs were not invoked. `qc_source_evidence.json` records 79 executed local source assertions. Runtime and archive evidence are tracked separately; a source review is not an Oracle score.

Analytic floor check: a static presentation with theme, pane sizing and editor syntax can collect at most 2/49.5 functional points, below the 0.05 floor. A partial product with genuinely working multiline indentation can exceed that floor and has an upper-bound reward near 0.436 with perfect presentation. This describes a partial editor, not a measured candidate-model result.
