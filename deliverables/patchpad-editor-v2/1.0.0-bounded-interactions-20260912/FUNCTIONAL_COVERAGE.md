# Functional coverage map

Reviewed 2026-09-12 against all 27 current criterion descriptions in [functional/judge.toml](../../../projects/patchpad-editor-v2/tests/functional/judge.toml). This is a source-to-test coverage audit, not an Oracle score. The new [broad run results](regression-results.json) record eight successful suites and 50 PASS labels. The separate [bounded results](bounded-results.json) record 13 successful groups: three repetitions of each current sample, six historical stronger-sample checks and one deliberately misplaced-caret diagnostic. Counts include supplemental and negative controls; they are not counts of independently passed rubric criteria. No golden application code was changed for this audit.

The selected scripts collectively exercise every Functional behavior family. They do not independently reproduce every criterion's complete procedure and evidence requirements. In particular, most historical scripts use the golden app's known DOM selectors and JSON routes, read authoritative responses from the current tab, and combine related checks. S adds independent fresh-context server-response/history snapshots, and B now compares independent persisted snapshots and the post-reload draft before/after every test. The verifier still requires criterion-specific evidence; these local helpers are appropriate for golden regression testing, not as replacement graders for arbitrary submissions.

## Running and interpreting the helpers

Run each historical suite against a fresh disposable container/app database: A and Q expect initial revision 1, and several suites intentionally save. The [historical runtime wrapper](../1.0.0-docketlight-procedures/browser-runtime.py) runs solve/start/stop around each script and expects copied script inputs under a new writable `/results`. Never bind a historical evidence folder as writable `/results` for a new run; outputs have fixed filenames.

B is an exception: it runs `solve.sh` and starts its own Node server. Run it standalone in a clean container, not underneath a wrapper that already started the lifecycle server. Running both together risks a port collision and database reset. The other scripts require a running golden app at localhost:3000, the existing image's `/usr/local/bin/chromium`, its preinstalled Playwright module, and browser clipboard permissions. R additionally requires the verifier lifecycle helper and writable PID/log directory with appropriate process permissions.

Retain logs as well as result JSON. O and Q can fail before writing their final JSON. The second Restore variant in O can observe an old success message; request/UI completion should be checked if that diagnostic flakes. Historical click helpers assume golden CSS padding and font geometry; B measures actual rendered text boundaries and records caret offsets. No script's process exit alone establishes full rubric coverage.

The revised four-line selection and adjacent two-caret descriptions are consistent with the unchanged golden logic. The mouse criterion explicitly permits contiguous trailing text beyond its target, while the keyboard criterion requires exactly four complete lines. The deletion criterion still requires both keys, all active carets, unchanged other lines, and one Undo after each mutation; the separate three-caret typing/Undo/Redo criterion remains intact.
