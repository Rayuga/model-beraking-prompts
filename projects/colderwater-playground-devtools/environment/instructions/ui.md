# Editing code

I want the editor to be the playground's own. Please draw the code yourself, with your own DOM, canvas or SVG text model, rather than putting it in a textarea, an input or a contenteditable element, and please don't bring in CodeMirror, Monaco, Ace, ProseMirror, TipTap, Quill, Slate, Draft.js or any other ready-made editor. A small hidden input that only catches keys or the clipboard is fine, as long as the code I look at is drawn by your surface. Parsing, highlighting and formatting libraries are welcome; the caret, selection, edits and undo are the part I want you to write.

I like seeing numbered lines and where I am. Show the current line and column, both counted from one, so the very start of the file reads line 1, column 1. Typing, pasting, new lines, Backspace, Delete, the arrows, Home and End should all behave as they do in any code editor, and Ctrl+Home and Ctrl+End (Cmd on a Mac) take me to the start and end of the file. Shift with the arrows extends a selection. When I move up or down through a shorter line, I expect to come back out at the column I started from. Emoji and accented letters made of a letter plus a combining accent should move and delete as one character, the way they look. When typing or moving takes the caret past the edge of a long line or a tall file, scroll so I can still see it.

With the mouse I click to put the caret in text, double-click to select a word, triple-click to select a line, and drag to select a range. I copy a selection with the usual shortcut. When I type or paste over a selection, it replaces it, and undoing a paste takes one step even when it was several lines. I often have one very long line, so keep it on one line and let me scroll sideways to select and edit text near its end. Tab and Shift+Tab indent and outdent every line my selection touches, in one undoable step, even when the selection sits inside a single line; if my selection ends at the very start of the next line, leave that next line alone.

I use multiple carets a lot. Alt+Click and Ctrl/Cmd+Click should both add a caret, on other lines or at several places on one line. Typing, Backspace and Delete then happen at every caret, and each caret stays with its own text when an earlier caret on the same line pushes it along. Everything I type at those carets in one go is a single Undo step, however slowly I type, and Redo brings it back. I use Undo and Redo both from buttons and from the usual shortcuts. For plain single-caret typing, undoing it in one step or a character at a time are both fine with me. After an Undo, the caret goes back to where it was before that edit, so I can carry on typing in the same place. Please grey out Undo and Redo whenever there is nothing to undo or redo, including straight after New or after opening a saved snippet. Formatting a file that is already formatted should change nothing and add no Undo step.

I need Find with next and previous, Replace current and Replace all, for exact, case-sensitive text; dots and brackets in what I search for are just those characters. The current match is selected in the editor, and stepping past the last match wraps round to the first. Replace current changes just the current match and then moves on to the next one. Sometimes my replacement contains the text I searched for; Replace all should still change each original match exactly once, and Replace current should never land on text it has just put in. Replace all is one Undo step, and if I make a new edit after undoing, Redo has nothing left to redo.

Colour the code by what each piece is, in colours that are clearly different from each other and from plain names: JavaScript keywords, function names (the same colour where a function is declared and where it is called), strings, numbers and comments; and in HTML, tag names, attribute names, quoted values and comments. A function name shouldn't look like a keyword or a string. The palette is up to you. Colouring is only for reading; it shouldn't change the saved code or what runs.

I paste a lot of compact one-line experiments, so I'd like Format document for valid JavaScript and for complete HTML files. It should spread the code over readable lines with consistent two-space nesting, and keep strings, comments and what the code does exactly as they were. Formatting a second time shouldn't change anything more. One Undo brings back the whole file as it was before formatting, and Redo applies it again. If my JavaScript has a syntax error, tell me why formatting didn't work and leave my draft exactly as it was. A standalone formatter is fine.

Around the editor I need title and filename fields, Run, Stop, New, Save, the saved library and a way to look at a snippet's history. Label the controls clearly and show where keyboard focus is. Since Tab indents inside the code, give me a keyboard way out of the editor to the next control, and show that shortcut on screen. After Run, Save and Format, tell me in words what happened, not only when something goes wrong. After Format, Undo, Redo, a replacement or Save, put me back in the code so I can keep typing at the caret. Show clearly when my draft differs from what is saved; that sign goes away after I save, and also when Undo takes the code back to the saved text. I sometimes check things on my phone, so at about 390 px wide the editor and its controls, the preview, the console and the library should all still be usable without the page scrolling sideways.
