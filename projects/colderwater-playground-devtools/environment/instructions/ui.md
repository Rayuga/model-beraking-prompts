# Editing code

Build the code editing surface with your own DOM, canvas or SVG text model. Don't use a textarea, input or contenteditable element as the document surface, and don't use CodeMirror, Monaco, Ace, ProseMirror, TipTap, Quill, Slate, Draft.js or another ready-made editor. A small input solely for keyboard or clipboard plumbing is fine as long as the source I see is drawn by your own surface. Parsing, highlighting and formatting libraries are allowed; the editing surface and its caret, selection, changes and undo behaviour are yours to implement.

Show numbered logical lines and the current line and column. Support normal typing, paste, new lines, Backspace, Delete, arrows, Home and End. Shift with the arrow keys extends a selection. Moving vertically should remember the intended column when a shorter line temporarily clamps it. Emoji and decomposed accented letters should move and delete as complete visible characters. The caret must stay in view: when typing or moving takes it past the visible edge of a long line or a tall file, the editor scrolls to follow it.

Use ordinary mouse actions to put the caret in text, select a word with a double click, select a logical line with a triple click, and drag a range. Copying a selection with the usual keyboard shortcut should work. Typing or pasting over a selection replaces it, and a paste is one Undo action even when it has several lines. The editor must keep a long unwrapped line horizontally reachable so text near its end can be selected and edited. Tab and Shift+Tab indent and outdent every line a selection touches as one undoable action, including a selection that sits inside a single line; a selection ending at the start of the next line should leave that next line alone.

Allow both Alt+Click and Ctrl/Cmd+Click to add carets, on different lines or at several places in one line. Typing, Backspace and Delete affect all of them, and each caret stays with its own text when an earlier caret on the same line shifts it. A continuous multi-caret typing burst is one Undo action; Redo restores it. Undo and Redo also work from visible controls and normal keyboard shortcuts. A run of ordinary single-caret typing may be undone in one step or character by character, whichever you prefer. Undo puts the caret back where it was before the undone edit, so typing straight after Undo lands in the original place. The Undo and Redo controls are disabled whenever there is nothing for them to do.

Offer Find, next and previous matches, Replace current and Replace all for literal case-sensitive text; characters such as dots and brackets in the search text mean only themselves. The current match is selected in the editor. Navigation wraps at the ends. Replace current changes only the current match and then moves to the match that follows it. When the replacement text itself contains the search text, Replace all still changes each original match exactly once and Replace current never lands on text it has just inserted. Replace all is one Undo action, and a new edit after Undo clears Redo.

Colour code according to what the tokens are, using visibly distinct treatments: JavaScript keywords, function names (coloured the same at their declaration and at calls), strings, numbers and comments; HTML tag names, attribute names, quoted values and comments. Function names should not be coloured as keywords or strings. Choose your own palette; no exact RGB value is required. Colouring is for the editor only and must not change the saved source or preview result.

Provide Format document for valid JavaScript and complete HTML. It should break a compact one-line program into readable lines, use consistent two-space nesting and preserve strings, comments and runtime meaning. Formatting twice should not change the result again. One Undo restores the whole pre-format source; Redo reapplies it. For a JavaScript draft with a syntax error, show a useful formatting error and leave the draft exactly as it was. A standalone formatter is allowed.

Include title and filename fields, Run, Stop, New, Save, a saved library and history inspection. Label controls clearly and show keyboard focus. Because Tab indents inside the code, give a keyboard way to leave the editor for the next control and show on screen what it is. After Run, Save and Format, say in words what happened, not only when something goes wrong. After Format, Undo, Redo, a replacement or Save, put keyboard focus back in the code so typing continues at the caret. Show clearly whether the draft differs from what is saved; that marker goes away after Save and when Undo brings the source back to the saved text. At a phone width of about 390 px the editor and its controls, the preview, the console and the library must all stay usable without sideways page scrolling.
