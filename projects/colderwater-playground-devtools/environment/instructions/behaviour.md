# Running and saving

Run the current .js source in a fresh isolated preview document. A complete .html file replaces that document. The browser may execute supported code in the preview; the editor must continue to hold the exact source used for Run. Nothing from an earlier run, neither its page content nor its variables, carries into the next one. Running a draft that has a syntax error shows a useful error and leaves the draft as it was. Show console output in the order it was written. Errors go to that same console: show a useful error message there with a one-based line number for a thrown error, including an error inside a complete HTML file, counted from the first line of that file, and a Promise rejection that nothing handles; the message is the text of the Error or rejected value, not an empty object. Output written before a run fails, is stopped or runs out of time stays in the console.

Keep the latest successful preview as a last-good picture. If a later run throws, is stopped or exceeds the five-second run budget, show the reason and restore that picture, including values typed into its controls and ordinary canvas drawing. The budget covers source execution and pending timer or Promise callbacks until that run settles. After it settles, a later user interaction in the preview starts a fresh five-second budget for its own callbacks. A restored picture may be static. The workspace must accept a later valid Run.

Stop ends the current run at once. Timers, intervals and Promise callbacks still pending from a stopped run must never change the preview or the console afterwards. The same holds when a newer Run replaces an older one that is still waiting: the older run must not later overwrite the newer preview or add console output.

Save a snippet's exact title, filename and source. A fresh page must read the saved record from the running app, and saved work and history must survive a complete server restart. Two tabs may load the same revision. One tab's later successful Save must make the other's old-revision Save fail without changing the saved record or discarding that tab's dirty draft. Give useful conflict feedback.

When another tab saves, the library in tabs that are already open should show it within about five seconds without a reload. That refresh must not touch what I'm doing: the draft, caret, scroll position and Undo history stay as they were, and the title and filename fields keep what I typed. If the snippet I have open gained a newer revision elsewhere, say so and keep my draft; do not load the newer revision over my work.

History inspection is read-only and shows that snapshot's title, filename and source. Restoring an older snapshot creates a new current revision of the same record while retaining the intervening history. An old-revision restore must not overwrite a newer save. If the same restore request is sent again after it was already committed, for example after a lost reply, it must not create another revision.
