how the box works - read before you start
-----------------------------------------

Cal asked me to write this down because the last two people both guessed and
both guessed differently. This is not a preference list, it is what will boot.

Where it goes
  /app. That exact path. The deploy script cds into it directly.

What to build it with
  TypeScript on the browser side, bundled with esbuild. The funnel is drawn with
  d3 - we already licence nothing and I am not adding a chart library for one
  chart. Express on the server, SQLite on disk.

  Node and the server packages are on the box already. Declare what you use in a
  package.json. Network access and package installation are allowed during
  development. Deliver the built browser bundle and server dependencies;
  starting the delivered server must not require a package install.
  Public scripts, styles, fonts, images and browser requests are allowed.
  Authentication and hiring records must remain on this local Node/SQLite app.

How it starts
  During development: npm run build
  Delivered startup: node /app/backend/server.js

  Build before handoff; the runner starts the server without rebuilding.
  It listens on 0.0.0.0:3000. It serves the browser side out of
  public/index.html and normally keeps its database at /app/pellmoor.db. The
  runner may provide DB_PATH when it needs another writable location; use that
  path when it is present.

  Put APP_MANIFEST.md beside package.json. Include a fenced bash start block,
  the line 'SQLite path: /app/pellmoor.db', and the actual methods and routes
  for login, logout, vacancy and candidate reads, creation, stage changes,
  panel additions and removals, scores and notes. Shared routes are fine.
